## Project

Tenancey is a test and learning project. Its purpose is to work out a **multi-tenant, multi-database**
Laravel setup using [stancl/tenancy](https://tenancyforlaravel.com/) v3 (v3.10.1+ supports Laravel 13).
The stack is Laravel 13 on PHP 8.4 with MySQL. **React + TypeScript comes later**, so don't add it until asked.

Phases:
1. Environment, DB access, frontend build, Node pinning: **done**.
2. Tenancy mechanism (central/landlord DB plus one database per tenant): **next**.
3. React + TypeScript frontend.

## Environment

- Served by Valet at **http://tenancey.test/** (`APP_URL`). Don't use `php artisan serve` for browsing.
- MySQL `127.0.0.1:3306`, user `root`, empty password. The central (landlord) DB is **`tenancey`**.
- **The MySQL server is shared with other projects.** cpcsl-cms already owns databases named
  `tenant_<uuid>`, so this project must use a distinct tenant DB prefix (e.g. `tenancey_tenant_`) in
  `config/tenancy.php`. Never drop databases by pattern.

## Frontend / Node

- Node **22.12.0** is pinned in `.nvmrc`. A `chpwd` hook in `~/.zshrc` auto-switches on `cd`, and the
  system default stays 20.19.4. In a non-interactive shell, run `source ~/.nvm/nvm.sh && nvm use` first.
- `npm run dev` does a **one-shot** development build (unminified) into `public/build`, then exits.
  The app keeps working with no process running.
- `npm run watch` rebuilds on change. `npm run hot` starts the Vite HMR server. `npm run build`
  makes the minified production build.
- `composer dev` / `php artisan dev` runs `npm run hot` (overridden in `AppServiceProvider`).
- If pages try to load assets from `localhost:517x`, a stale `public/hot` file is the cause: an HMR
  server was killed uncleanly. Delete it.
